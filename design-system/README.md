# מערכת העיצוב של האתר — `design-system/` · גרסה 2026-09-29

**מ-2026-09-29 זו מערכת העיצוב היחידה של האתר.** היא פלטת הרכיבים הממוספרת ("פלטת רכיבים גמ״ח שמלות", https://claude.ai/artifact/H6toH2q9ZvL8rrFwZx3SBj), שנסרקה מה-DOM החי של שני דפי ה-v3 שהבעלים אישר: **דף הבית וסיכומים A5** (https://claude.ai/artifact/GscpxuJVsbVxxc9VgcEtDB) ו**כרטיס ההזמנה** (https://claude.ai/artifact/5sG47Yyn1HsjyS6GR6ygqh). כל רכיב בה הוא HTML שרץ בפועל באחד הדפים, עם ה-CSS שחל עליו בפועל (כ-990 כללי CSS "מתים" ו-49 מחלקות ישנות הוסרו).

ה-CSS הישן של האתר — `app/design-system.css`, `app/design-overrides.css`, `app/globals.css`, ה-sprite ב-`app/components/IconSprite.js` (שכבת "design-v2 / אריג") — הוא **שכבת legacy**: הוא ממשיך לעצב את הדפים הקיימים כפי שהם, ולא נוגעים בו. **דף חדש או דף שמעצבים מחדש נבנה מרכיבי הפלטה לפי המספר הסידורי** ("לחצן 12", "אייקון 23", "באנר 3"), לא מרכיבי ה-legacy.

## איך משתמשים בדף חדש

1. **טוקנים** — זמינים בכל דף באתר (`app/globals.css` מייבא את `tokens.css`): `color: var(--gm-navy)`, `border-radius: var(--gm-r)`, `box-shadow: var(--gm-sh)`. השם המקורי של הפלטה מקבל תמיד את הקידומת `--gm-` (`--gold-300` → `--gm-gold-300`; המספר בקטלוג: "צבע 12").
2. **רכיבים** — בדף (או ב-layout) שמשתמש ברכיבי הפלטה:
   ```js
   import '@/design-system/components.css';   // רק בדפים שצריכים; לא גלובלי (450KB, ראו "היקף")
   ```
   ```jsx
   <div className="gm-ds">…רכיבי כרטיס ההזמנה…</div>
   <div className="gm-ds gm-home">…רכיבי דף הבית…</div>
   ```
   ואז מדביקים את ה-HTML של הרכיב מהפלטה ("העתק HTML") או מ-`COMPONENTS.md`, **עם שמות המחלקות כפי שהם** (`btn primary`, `card`, `seg pill`, `article.hrow.irow`). הקטלוג אומר לכל פריט באיזה עור הוא נתפס.
3. **אייקונים** — בתוך האפליקציה תמיד הפניה חיצונית ל-sprite, כי 30 מזהי `#i-*` של הפלטה (`i-mail`, `i-search`, `i-users`, `i-file`, `i-x` …) קיימים גם ב-`IconSprite.js` של ה-legacy ו-`<use href="#i-mail">` היה תופס את הישן:
   ```jsx
   <svg className="ic ia-mail ia-h"><use href="/design-system/sprite.svg#i-mail" /></svg>
   ```
   בדף סטטי שמטמיע את ה-sprite (כמו `index.html`) — `<use href="#i-mail"/>`. המחלקות `ia-<id> ia-h` נותנות את הנפשת הריחוף של האייקון (הנפשה N בקטלוג).
4. **התנהגויות** — הטולטיפ (`data-tip` / `data-rich`), הגלולה עם המחוון (`.seg.pill` + `--i`), הלשוניות, מתג התצוגה (`.vsw`) ולחצני הבחירה דורשים JS. המימוש המינימלי נמצא ב-`build/pl2.js` (הסקריפט של דף הפלטה); המימוש המלא — בשני דפי המקור.
5. **גופן** — `components.css` טוען את Rubik מ-Google Fonts (בכוונה לא `tokens.css`, כדי ששום דף ישן לא יטען גופן חדש).

## היקף ואפס-שינוי בדפים קיימים ("no-collision guarantee")

הפלטה משתמשת בשמות מחלקה קצרים שקיימים גם ב-CSS הישן — 30 משותפים: `btn, card, chip, badge, tab, tabs, seg, field, stepper, step, topbar, hero, main, grid, on, off, open, active, done, pending, success, info, danger, muted, meta, dot, today, block, lg, sr-only`. לכן:

1. **שורש היקף.** כל אחד מ-5,496 חלקי הבורר ב-`components.css` מתחיל ב-`.gm-ds` (בדיקה אוטומטית: `python design-system/build/check_collisions.py`). דף קיים לא מכיל אלמנט עם המחלקה `gm-ds` (0 מופעים בקוד `app/` ו-`components/`), ולכן אף כלל לא חל עליו. בתוך `.gm-ds` הפלטה מנצחת כלל legacy באותו שם בזכות ספציפיות גבוהה יותר (`.gm-ds .btn` = (0,2,0) מול `.btn` = (0,1,0)).
2. **שני עורות, כמו בפלטה.** `.gm-ds` לבדו = העור של כרטיס ההזמנה (הבסיס). `.gm-ds.gm-home` = הקסקדה **המלאה** של דף הבית, כשכבה מעל הבסיס בספציפיות +1 — כך רכיב של דף הבית נראה בדיוק כמו בדף הבית (הלחצנים, הצ'יפים והטבלאות שונים מעט בין שני הדפים; הפלטה מציגה כל רכיב בעור הדף שלו וכך גם כאן). 19 כללי `!important` של כרטיס ההזמנה שהיו דורסים את עור הבית מוגבלים ל-`.gm-ds:not(.gm-home)`. רכיב שקיים רק בכרטיס ההזמנה זמין גם בתוך `gm-home`.
3. **שמות גלובליים מקודמים.** `@keyframes` — כולם `gm-<שם>` (הנפשה 47 `fade` → `gm-fade`); הטוקנים — `--gm-*`; `@property --a` → `--gm-a`. חיתוך עם ה-keyframes (10) והמשתנים (111) של האפליקציה: ריק.
4. **בלי `@layer`, בכוונה.** כלל בתוך `@layer` מפסיד תמיד לכלל לא-משוכב, ולכן `.btn`/`.card` של ה-legacy (שנטענים בכל דף דרך ה-layout הראשי) היו דורסים את הפלטה בכל דף חדש. ההיקף בשורש כבר מבטיח אפס שינוי בדפים קיימים; ה-`@layer` היה מוסיף רק נזק.
5. **הגשר `.gm-ds{--navy:var(--gm-navy) …}`** ב-`tokens.css` קיים כדי ש-`style="color:var(--ink)"` ב-HTML שמעתיקים מהפלטה יעבוד; הוא תקף רק בתוך שורש `gm-ds` (שם גם `--surface`/`--bg` של ה-legacy מקבלים את ערכי הפלטה — זה רצוי בתוך רכיב פלטה).

**איך אומת (2026-09-29):** (א) `python design-system/build/check_collisions.py` — 5,496 חלקי בורר, כולם תחת `.gm-ds`; חיתוך keyframes/טוקנים/ids עם ה-legacy ריק; 0 מופעי `gm-ds` בקוד. (ב) שרת dev (worktree, פורט 3020, TEST DB) עם **גם `tokens.css` וגם `components.css` מיובאים גלובלית** מ-`globals.css`: בארבעה דפים אמיתיים (`/`, `/orders`, `/customers`, `/admin/site`, viewport 1280×900) נדגמו 173–300 אלמנטים מרכזיים לדף (html, body, ניווט, כותרות, לחצנים, קישורים, שדות, טבלאות, כרטיסים, `div`/`span`) עם 40 מאפייני `getComputedStyle` + גודל התיבה של כל אחד; ואז נמחקו מה-stylesheet החי כל 3,998 כללי הפלטה (כולל הטוקנים, ה-keyframes, ה-`@property` וייבוא Rubik — `--gm-navy` נעלם) ונדגם שוב על אותו DOM בדיוק: **0 אלמנטים השתנו בכל אחד מארבעת הדפים** (רצפת רעש 0). לכן `components.css` בטוח גם לייבוא גלובלי; במצב המחויב מיובא רק `tokens.css`, ו-`components.css` נשאר לייבוא לפי דף בגלל גודלו (455KB).

## כלל יציבות המספור

`build/numbers.json` הוא **מרשם המספרים**: לכל קטגוריה (לחצן, בורר, תגית, שדה, באנר, טוסט, טולטיפ, רמז עשיר, חלון, כרטיס, שורה, היסטוריה, שלב, ניווט, בית, פריט, אייקון, הנפשה, צבע) מפתח יציב של הרכיב ← מספר. **לעולם לא ממספרים מחדש.** רכיב חדש מקבל את המספר הבא; רכיב שנעלם מהדפים משאיר את מספרו פנוי לצמיתות. כך "לחצן 12" ישאר `a.lnk` של דף הבית גם בעוד שנה. `build/serial_map.json` הוא המפה ההפוכה שנוצרת בכל בנייה (מספר → בורר/דף/טקסט).

ב-2026-09-29 נוספו **אייקון 68–71** (`i-sn-bug`, `i-sn-chart`, `i-sn-history`, `i-sn-inv`): ארבעה סמלי תפריט שקיימים בשני הדפים אבל `build2.py` פספס אותם (ה-regex שלו `i-([\w]+)` לא תפס מזהים עם מקף). `install.py` קוצר את ה-sprite ב-regex על כל ה-`<symbol>` ומוסיף למרשם כל סמל חסר.

## איך מחדשים (כשהפלטה או הדפים משתנים)

הצינור המלא (פירוט ב-`build/README.md`): `crawl.mjs` (סריקת הדפים החיים ב-Edge headless) → `mkcss.py` (CSS נקי ומוגדר-היקף לכל דף) → `extract.py` (בחירת הרכיבים) → `anim_data.py` → `build2.py` (הרכבת דף הפלטה + `numbers.json`) → `install.py` (הקבצים שבתיקייה הזו). הצינור דורש עותקים מקומיים של שני דפי המקור בשם `pageA.html` / `pageB.html` (ה-Artifact tool שומר אותם בקריאת `read`; הם לא בריפו — 1MB כל אחד). כשמשנים רק את דף הפלטה (הארטיפקט) מספיק להריץ את `install.py` על שלושת הקבצים השמורים. אחרי כל בנייה: `python design-system/build/check_collisions.py`, עדכון `VERSION` ב-`install.py`, וקומיט של כל התיקייה יחד עם `public/design-system/`.

## פערים ידועים

- הסריקה תפסה רק מצבים שמגיעים אליהם בקליקים, בבחירות של סרגל ההדגמה, בהקלדת חיפוש, במצב נייד ובריחוף; חלונות שדורשים תהליך ארוך (למשל תשלום מלא) ייתכן שחסרים. הנפשות מוצגות בפלטה על אלמנט הדגמה ולא על הרכיב האמיתי.
- 5 אייקונים בספרייה לא מופיעים באף מצב (אייקון 22 `i-eraser`, 50 `i-searchspark`, 69–71 סמלי תפריט); הם ב-sprite ומסומנים "לא בשימוש".
- רק 18 טולטיפים ו-10 רמזים עשירים ממוספרים (אלה שנתפסו בריחוף); `data-tip` אחרים בקטלוג מסומנים "(לא ממוספר)".
- כללי `html{}` לא ניתנים להגדרת היקף: צבע הרקע של `html` בדף הבית (`#f6d9cb`) אינו ב-`components.css`; `.gm-ds.gm-home.home-bg` מקבל רקע שקוף ואת התמונה ב-`::before`.
- הטולטיפ בפלטה הוא `.pl-tt` / `.pl-rt` (בדפים האמיתיים `#tt` / `#rt` שנוצרים ב-JS) — `components.css` שומר על שמות הפלטה.
- סרגל ההדגמה (`.demo`, ניווט 4/47) הוא פיגום של אבות-הטיפוס ולא רכיב של האתר; הוא בפלטה ולכן גם כאן.
- `components.css` מכיל את שני העורות במלואם (455KB לפני מינימיזציה) — לכן מייבאים אותו רק בדפים שצריכים.
