# היסטוריית שאילתות ו-API (`/management/history`) - notes

**זה לא יומן שינויים** (זה `/admin/data-history`): הדף מציג את `PageVisitLog` - כל קריאת API וכל ביקור במסך (נתיב, מי, נפח הנתונים שחזר, משך ביצוע, תקלה, פרמטרים שנשלחו). שימושו: איתור שאילתות כבדות / איטיות / שבורות. הישן: טבלה עם 8 עמודות, 60 לעמוד, ברירת מחדל "שאילתות API בלבד".
קבצים: `app/components/history-lists/{ManagementHistoryA5,ManagementHistorySwitch,visitLogLogic,historyShared,PinDialog,history-lists.css}.js`, `lib/adminVisitList.js` (טהור), `lib/adminVisitListServer.js`, `lib/adminLogList.js` (משותף),
`app/api/admin/management-history/{route,counts/route}.js`, `app/components/a5-print/pkSpecsHistory.js` (`visitLogDoc`), `app/management/history/{page,LegacyManagementHistoryPage}.js`. בדיקות: `scripts/test_a5_history_lists.mjs`.

## מה המסך עושה (כל היכולות של הדף הישן נשמרו)
* שורה 1: נתיב ה-API (`/api/admin/orders-list`, LTR) או שם המסך בעברית ("הזמנות", "לקוחות"...) בביקור; אייקון: API / ביקור / תקלה. שורה 2: מתי (יום עברי + שעה), מי (אורח = "אורח"), נפח (כתום מעל 100KB, אדום מעל 1MB - כמו הישן), משך (ms), תקלה (טקסט קצר). **תקין / ריק לא מופיע** (בישן "תקין (200 OK)" בכל שורה).
* חץ פרטים = מחליף את החלון "הצג פרמטרי שאילתה": מתי (יום + שעה), סוג, נתיב מלא, עובד, נפח, משך, תקלה, **הפרמטרים שנשלחו** (גוף הבקשה אחרי הסתרת סודות), "מחיקת הרשומה".
* סינון (חלון אחד): סוג (שאילתות API [ברירת מחדל, כמו הישן] / ביקורי מסכים), מצב (עם תקלה / תקין - חדש), עובד (כולל "אורחים"; 30 הפעילים ביותר), תקופה (עברית). מיון: זמן, עובד, נתיב, נפח, משך, תקלות (= 6 העמודות הממוינות בישן; יום בשבוע התמזג לעמודת הזמן - "יום ראשון ל׳ תשרי"). חיפוש: נתיב / שאילתה / שגיאה (כמו הישן) + שם עובד (חדש).
* **ניהול רשומות** (3 המחיקות של הישן): לחצן בסרגל התוצאות פותח חלון כהה: "בחירת רשומות למחיקה" (תיבות בחירה בשורות / בטבלה + "בחר את העמוד" + "מחק נבחרים (N)" + "סיום בחירה"), "מחיקת רשומות ישנות מ-90 יום", "מחיקת כל ההיסטוריה". כל מחיקה דורשת קוד מנהל בחלון כהה (`PinDialog`, במקום `customAuthPrompt` הבהיר) ומגיעה ל-`DELETE /api/history` **ללא שינוי** (אותו חוזה: `username` = העובד המחובר, `password` = הקוד; מנהל סניף עם קוד נכון מותר, כמו בישן). הקוד לא נשמר ולא נרשם.
  התראת "מעל 10,000 רשומות" נשמרה כלחצן "היומן גדול" בכותרת הכרטיס (טולטיפ עם הנוסח; לחיצה = "ניהול רשומות"); הספירה = אומדן סטטיסטי של Postgres, לא COUNT.
* ייצוא: Excel (עד 5,000) / PDF / הדפסה (עד 1,500 שורות, מעל זה חלון "צמצמו את הסינון") = "יומן שאילתות ו-API" מקובץ לפי יום, עמודות שעה / עובד / נתיב או מסך / נפח / משך, "תקלה" רק כשיש תקלות. משטח PDF `a5-management-history` -> `page:admin`.
* לא נבנה: חיפוש חכם / סטטיסטיקה (אין backend ליומן).

## גישה, הרשאות, סודות
* הדף: `app/management/layout.js` (הנהלה ראשית / מתכנת). ה-API החדש: `checkAuth('הנהלה ראשית')` (401 לכל השאר, נבדק חי - ר' data-history-notes). 
* **תיקון אבטחה (R8 של security-audit.md):** `GET /api/history` היה פתוח לכל עובד מחובר (נתיבים, גופי בקשות, שמות) - עכשיו `checkAuth('הנהלה ראשית')`. הדף הישן הוא הצרכן היחיד והוא כבר הנהלה בלבד, ולכן אין שינוי למשתמש. `DELETE /api/history` לא שונה.
* גופי בקשה ונתיבים עוברים `redactRequestQuery` / `redactUrl` בשרת (כמו בישן) לפני שיוצאים; חיפוש בגוף בקשה אסור כשהנתיב הוא login / auth / attendance או שהגוף מזכיר סיסמה / pin / token / ת"ז / בנק / כרטיס (הרשימה זהה ל-`/api/history`, נבדקת בבדיקה) - נבדק חי: חיפוש "BODYSECRET" של גוף עם סיסמה = 0 תוצאות, והסיסמה בגוף מוצגת "[מוסתר]".
* מחיקה נבדקה חי מול TEST (שורות בדיקה שנוצרו ונמחקו): אנונימי 401, בלי קוד 401, קוד שגוי 401, קוד של הנהלה כ"מזכירה" 401, ימים לא תקינים 400, בלי בחירה 400, קוד נכון + 2 מזהים 200 ונמחקו בדיוק הם.

## עלות
`PageVisitLog` גדלה בכל ביקור / קריאת API (TEST: 45k שורות; PROD - לא נבדק). אינדקסים: `timestamp`, `employeeId`. אותם מנגנוני הגנה כמו `data-history-notes.md` (timeout, 4 במקביל, סך חסום ל-100,000 עם מטמון 30 שנ', ספירות רק כשהחלון פתוח, עמוד עד 100). מדידות (EXPLAIN ANALYZE, TEST 45k שורות): רשימה ברירת מחדל (api, לפי זמן) **0.12 ms** (סריקה לאחור על `PageVisitLog_timestamp_idx` + incremental sort), תקופה 7 ימים 0.13 ms, עם תקלה 3.6 ms, חיפוש נתיב 0.4 ms, מיון לפי נפח 13.7 ms (סריקה מלאה + top-N); count חסום 1.6-39 ms.
| בקשה | לפני (`GET /api/history`, 60) | אחרי (`/api/admin/management-history`, 50) |
|---|---|---|
| שאילתות לעמוד | count (מסונן) + findMany + **count(*) של כל הטבלה** = 3 | שורות (1) + count חסום (1, מטמון 30 שנ') + אומדן reltuples (עמוד 1 בלבד, מטמון 5 דק') |
| תשובה | 26.8 KB (60 שורות כולל `requestQuery` מלא) | 16.6 KB (50 שורות, גוף נחתך ל-6,000 תווים לפני העיבוד) |
* `select` מפורש בלי עמודות המדידה (`serverCpuMs`...): ב-TEST אין אותן (schema drift) - הקריאה הישנה והחדשה לא נשברות.
