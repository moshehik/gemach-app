# חוזה: מסך הכניסה (archetype-login)

ענף: `redesign/v3-proto-login` (מבוסס על `redesign/v3-protos-review`). קובץ האב-טיפוס: `archetype-login.html`. שאלות ובחירות ברירת מחדל: `LOGIN-QUESTIONS.md`.
**לא שונה שום קוד אפליקציה, API, Prisma או נתונים.** המסמך נכתב מקריאת הקוד בלבד (ללא DB, ללא אתר חי).

### א.3 מה העיצוב החדש אומר (תמצית)
1. **הרכב אחר לגמרי: "שער" דו-אזורי ולא כרטיס על רקע.** אזור זהות navy בגובה מלא (צד `inline-start`, כלומר ימין) עם הלוגו ושם הגמח מתוך ההגדרות, ואזור פעולה בהיר רחב בצד השני. במסך צר אזור הזהות הופך לרצועה עליונה נמוכה. אין aside שיווקי, אין "יתרונות".
2. **שני צעדים ברורים בתוך אותו אזור, צעד = פעולה ראשית אחת:** (1) **מי נכנס?** — רשימת שמות גדולה עם סינון (לא קומבובוקס קטן שנפתח ודוחף); (2) **הקוד** — "שלום, {שם פרטי}" + שדה אחד גדול. אותו state ואותן קריאות — השלבים הם הצגה בלבד (ר' LG-13, LG-20).
3. **מלל חדש וקצר**, נכתב מאפס (ר' §ג).
4. **"מחשב מהימן" בלי צ'יפ**: שורת מידע שקטה בתוך צעד הקוד, עם ⓘ.
5. **מצבים מלאים**: טעינה (שלד), רשימה ריקה/לא נמצא/נכשלה טעינה, ולידציה, שגיאות שרת לפי הודעת השרת, רשת, שליחה, הצלחה (סימון מצויר ומעבר), שכחתי, סיסמה קבועה.
6. **תאימות מנהלי סיסמאות מתוכננת** (הבעיה הידועה — LG-30…LG-34): הפרדה בין שדה החיפוש (שנשאר מוגן מאוטופיל) לבין שדה `username` נסתר-ויזואלית שמחזיק את שם העובד שנבחר, ושדה סיסמה עם `current-password`. **ממתין להחלטת הבעלים** — באב-הטיפוס זה מתג בבקרת ההדגמה.

## ב. מלאי פונקציונלי (LG-1…) — מה חייב להישמר
"נשמר" = אותו state, אותה קריאה, אותה הסתעפות. מלל ומיקום — חופשיים (נכתבו מחדש).

### ב.1 נקודות כניסה והקשר
- **LG-1** שני מצבי הצגה מאותה קומפוננטה: עמוד מלא (ברירת מחדל) וחלונית (`isModal` + `onClose`). בחלונית: כפתור סגירה רק אם יש `onClose`, קורא `onClose(false)`; לחיצה על הרקע **לא** סוגרת. (Esc סוגר היום ב-v3 — שינוי מהישן, ר' `reports/verify-login.md`; ההחלטה ב-LOGIN-QUESTIONS Q-L7.)
- **LG-2** עמוד מלא מוצג **במקום** הדף המבוקש (`showLogin` ב-layout), ה-URL לא משתנה; פטורים: `/customer-interface/*`, `/punch-clock`. ערכת נושא בהירה כפויה.
- **LG-3** אחרי הצלחה: `window.location.reload()` — לא ניווט, לא `router.refresh` (navbar צד-שרת ו-`/api/me` במטמון). חוזרים לאותו דף שביקשו.
- **LG-4** קישור לשעון הנוכחות (`/punch-clock`) — **בעמוד מלא בלבד**.
- **LG-5** `dir="rtl"` על כל השכבות; מבנה `lang="he"`.
- **LG-6** רינדור ללא תלות ב-providers (`LoginScreen` נטען ב-layout מחוץ ל-`PopupProvider`/`LabelsProvider`) — הסגנונות גלובליים.
- **LG-7** זהות הארגון מגיעה מהגדרות בלבד: שם (`gmach_name`, ברירת מחדל קיימת בקוד השרת `'גמ"ח שמלות'`), לוגו (`BRAND_LOGO` דרך `/api/logo`). **כיום לא מוצגים בכניסה כלל** — העיצוב החדש מציג אותם; מקור הנתונים = props מה-layout (צד שרת, כבר קורא הגדרות) ולא API ציבורי חדש (Q-L3).

### ב.2 עובד
- **LG-8** רשימת עובדים מ-`GET /api/employees` (`fetchSharedJson`, `TTL.STATIC`); בזמן טעינה השדה מושבת; כישלון נרשם ב-console בלבד (העיצוב החדש מציג מצב "לא נטען" עם "לנסות שוב" — **תוספת לוגיקה קטנה, לאישור** Q-L5).
- **LG-9** למבקר אנונימי יש רק `id`, `firstName`, `lastName` — אין תמונה, תפקיד או סניף. מותר להציג ראשי-תיבות בלבד.
- **LG-10** סינון לפי הכלה (`includes`) של "פרטי משפחה" לטקסט שהוקלד; כשהשדה מציג בדיוק את שם הנבחר והרשימה פתוחה — מציגים את **כל** הרשימה.
- **LG-11** שינוי טקסט מאפס את הבחירה; בחירה קובעת `selectedEmployee` + הטקסט לשם המלא וסוגרת.
- **LG-12** `resolveEmployeeId`: אם לא נבחר אך הוקלד שם זהה בדיוק — נבחר אוטומטית (גם ב"שכחתי").
- **LG-13** ניקוי בחירה (כפתור עם `aria-label`) מאפס בחירה וטקסט ופותח את הרשימה. בעיצוב החדש = "לא אני — החלפת שם" בצעד הקוד (מחזיר לצעד 1 עם שדה ריק).
- **LG-14** הגנת autofill של שדה החיפוש: `name` אקראי שנוצר **רק ב-`useEffect`** (hydration) + `autoComplete="new-password"` (דיווחים 2a4a2af4, 0a88cf56). **אסור לשנות** — זה שדה חיפוש, לא שם משתמש.
- **LG-15** `id="login-employee"` ו-`data-element-name` (`שדה_LoginScreen_4`, `לחיץ_LoginScreen_6`, `לחיץ_LoginScreen_7`) — נדרשים ל-`useActionRecorder` ולדיווחי תקלה. כל ה-`data-element-name` מ-LOGIN-DESIGN §3.7 נשמרים.
- **LG-16** מקלדת ברשימה (תוספת נגישות, C-1.12/ד.8): `↑↓` Home/End, Enter בוחר, Esc סוגר/מנקה; `role=combobox/listbox/option`, `aria-activedescendant`.

### ב.3 קוד / סיסמה
- **LG-17** `GET /api/auth/device-status` בטעינה; `trusted` ⇒ `deviceTrusted=true` **ו-`usePinMode=true` כברירת מחדל**; כישלון = מתעלמים.
- **LG-18** מצב סיסמה מלאה: `id="login-password"`, `type=password`. מצב PIN: אותו `id`, `maxLength=4`, חיתוך ל-4 ב-`onChange`.
- **LG-19** מתג "קוד מקוצר ↔ סיסמה מלאה" — **רק** כש-`deviceTrusted`; מאפס `error`, `password`, `pinValue`.
- **LG-20** "שכחתי סיסמה" פותח את זרימת השכחה ומאפס `forgotResult`.
- **LG-21** הצגה/הסתרה של הסיסמה (כפתור עין עם `aria-pressed` + `aria-label` מתחלף) — קיים בקיוסק (`customer-interface:1543`), **חדש במסך הכניסה הראשי**; הצגה בלבד, לא משנה את הנשלח.

### ב.4 שליחה, תגובות שרת ושגיאות
- **LG-22** טופס אחד, Enter שולח, `e.preventDefault()`.
- **LG-23** ולידציה בצד לקוח: חסר עובד או קוד ⇒ שגיאה (PIN / סיסמה — שני ניסוחים), בלי קריאת רשת.
- **LG-24** `POST /api/login` עם `{employeeId, pin}` או `{employeeId, password}`.
- **LG-25** הצלחה = `res.ok && data.success`; `data.mustResetPassword` ⇒ זרימת סיסמה קבועה (שומרים `resetEmployeeId`); אחרת `finishLogin()`.
- **LG-26** כישלון: `data.requireFullPassword` ⇒ חוזרים למצב סיסמה מלאה ומנקים PIN; מציגים **`data.message` כלשונו** (ברירת מחדל אם חסר). הודעות השרת האמיתיות שהעיצוב חייב להכיל (כולל שבירת שורה):
  | סטטוס | `message` | הערה |
  |---|---|---|
  | 400 | `נא להזין קוד עובד וסיסמה` | לא אמור לקרות (ולידציית לקוח קודם) |
  | 404 | `עובד לא נמצא` | עובד נמחק בין טעינת הרשימה לשליחה |
  | 403 | `חשבון העובד אינו פעיל` | |
  | 401 + `requireFullPassword` | `מחשב זה אינו מוגדר כמערכת מהימנה - יש להזין את הסיסמה המלאה` | הודעה ארוכה (72 תווים) |
  | 401 + `requireFullPassword` | `לעובד זה טרם הוגדר קוד כניסה מקוצר. יש להזין את הסיסמה המלאה` | |
  | 401 | `קוד שגוי` (PIN) / `סיסמא שגויה` (סיסמה) | שים לב: "סיסמא" בכתיב השרת — המלל מהשרת לא נכתב מחדש כאן (שינוי שרת = מחוץ לתחום) |
  | 401 | `לעובד זה טרם הוגדרה סיסמה במערכת. אנא פנה למנהל.` | |
  | 500 | `שגיאת שרת` | |
- **LG-27** שגיאת רשת (fetch נכשל / JSON לא תקין) ⇒ הודעת רשת; `finally` מכבה `loading`.
- **LG-28** בזמן שליחה: כפתור מושבת + חיווי טעינה; אין שליחה כפולה.
- **LG-29** **אין נעילה אחרי ניסיונות** — העיצוב לא מציג מצב "נחסמת". (אם תתווסף בשרת — מקום מוכן: אותו אזור שגיאה, Q-L6.)

### ב.5 תאימות מנהלי סיסמאות ו-autofill (הבעיה הידועה)
- **LG-30 המצב היום:** כל השדות `autoComplete="new-password"` + הטופס `autoComplete="off"`. תוצאה: דפדפן/מנהל סיסמאות **לא מציע למלא ולא מציע לשמור** — בכוונה, כי ב-2026-09-22 נמצא שהחזרת `current-password` תחזיר את באג ה-dropdown הכפול (ר' CLAUDE.md "Feedback batch 2026-09-22"). **לא פתור — ממתין להחלטה.**
- **LG-31 הסיבה השורשית:** שדה החיפוש של העובד הוא גם "שם המשתמש" היחיד בטופס, ולכן אותו שדה צריך גם להיות מוגן מהיסטוריית הדפדפן וגם להיות מזוהה כ-username. אי אפשר את שניהם באותו input.
- **LG-32 מה העיצוב מאפשר (מוצע, באב-הטיפוס מאחורי מתג "תמיכה במנהלי סיסמאות"):**
  1. שדה החיפוש נשאר מוגן בדיוק כמו היום (LG-14).
  2. שדה **`username` נפרד**: `<input type="text" autocomplete="username" name="username" readonly tabindex="-1">`, מוסתר-ויזואלית בשיטת `sr-only` (**לא** `display:none` — מנהלי סיסמאות מתעלמים משדות מוסתרים כך), ערכו = שם העובד שנבחר (או ה-id), בתוך אותו `<form>` של שדה הסיסמה.
  3. שדה הסיסמה: `autocomplete="current-password"` ב**מצב סיסמה מלאה**; במצב PIN נשאר `one-time-code`/`off` (4 תווים אינם הסיסמה השמורה — אסור שמנהל ימלא בהם את הסיסמה המלאה ויקבל "קוד שגוי").
  4. הטופס בלי `autocomplete="off"` ברמת ה-form.
  5. צעד הקוד הוא **מסך נפרד מהרשימה** — כשהסיסמה מוצגת, רשימת העובדים לא על המסך, כך שה-dropdown של הדפדפן (אם יופיע ליד הסיסמה) לא מתנגש ברשימה המותאמת. זה בדיוק מה שגרם לבאג 2a4a2af4.
- **LG-33** הצלחה עם `current-password` אמורה להפעיל "לשמור סיסמה?" של הדפדפן אחרי `reload` — **לא נבדק בדפדפן אמיתי** (אב-טיפוס סטטי, אין שרת). בדיקה נדרשת לפני מימוש: Chrome + Edge + מנהל חיצוני אחד, עם שני עובדים שונים באותו מחשב.
- **LG-34** סיכון מוכר: מחשב משותף בגמח — שמירת סיסמאות של כמה עובדים באותו דפדפן. לכן זו החלטת בעלים (Q-L1), לא ברירת מחדל שקטה. ברירת המחדל באב-הטיפוס: **מתג כבוי = התנהגות היום**.

### ב.6 אחרי ההצלחה
- **LG-35** `finishLogin`: אם `notify_on_new_message_at_login==='true'` (דרך `/api/settings`) ויש הודעות לא-נקראות ולא-בארכיון — הודעה "מחכות לכם N הודעות…". **הערה:** היום זה async ו-`reload()` רץ מיד אחריו, כך שבפועל ההודעה כמעט לא מספיקה להופיע (Q-L4). העיצוב החדש לא מבטיח את ההודעה על מסך הכניסה; מקומה הטבעי = אחרי הטעינה (NoticeBar/פעמון) — שינוי לוגי, מחוץ לתחום אב-הטיפוס.
- **LG-36** אין `alert/confirm/prompt` בעיצוב החדש (היום נפילה ל-`alert()` כש-`customAlert` חסר).

### ב.7 שכחתי סיסמה
- **LG-37** דורש עובד (דרך `resolveEmployeeId`); בלי ⇒ הודעה "קודם בוחרים שם". בעיצוב החדש הזרימה נגישה רק מצעד הקוד, כך שתמיד יש עובד — ההודעה נשארת כהגנה.
- **LG-38** `POST /api/auth/forgot-password {employeeId}`; מציגים `data.message`. הודעות אמיתיות: הצלחה `סיסמה זמנית נשלחה לכתובת המייל השמורה`; 400 `לא קיימת כתובת מייל שמורה עבור עובד זה. יש לפנות למנהל.`; 502 `שליחת המייל נכשלה, נסה שוב או פנה למנהל`; 403/404/500 כנ"ל.
- **LG-39** כפתור שליחה מושבת בזמן שליחה ("שולחים…"); "חזרה" סוגר.
- **LG-40** בחלונית (`isModal`) — שכחתי יכול להיות תת-מסך בתוך אותה חלונית (לא חלונית שנייה) — בחירת הצגה; state זהה.

### ב.8 סיסמה קבועה (חובה אחרי סיסמה זמנית)
- **LG-41** **לא ניתנת לסגירה/דילוג** (אין X, אין Esc, אין "חזרה").
- **LG-42** שני שדות `login-newpass1`/`login-newpass2`, `type=password`, `autocomplete="new-password"` (כאן זה **נכון** סמנטית — ומאפשר למנהל סיסמאות להציע סיסמה חזקה).
- **LG-43** ולידציה: פחות מ-4 תווים; לא זהות. `POST /api/employees/${id}/password {newPassword}`; הצלחה ⇒ `finishLogin()`; אחרת `data.message`; רשת ⇒ הודעת רשת. כפתור מושבת בזמן שמירה.

### ב.9 קיוסק (לא באב-הטיפוס הזה, אבל חייב להתאים)
- **LG-44** חלונית "שחרור המסך"/"אישור עובד להדפסה" בקיוסק משתמשת באותה `/api/login` (סיסמה מלאה בלבד, אין PIN), Esc ורקע לא סוגרים, "ביטול" לא משחרר. כשימומש — אותם רכיבי שדה/כפתור/שגיאה של המסך הזה, בחלונית בהירה (D-2), עם יעד מגע 56 (`--v3-tap-touch`).

### ב.10 נגישות ומקלדת (דרישות העיצוב החדש)
- **LG-45** סדר פוקוס: צעד 1 — חיפוש → רשימה (חצים) → קישור משמרת. צעד 2 — "לא אני" → סיסמה → עין → מתג PIN (אם יש) → "שכחתי" → כניסה. פוקוס עובר אוטומטית לשדה הראשי של כל צעד. טבעת פוקוס זהב נראית תמיד.
- **LG-46** שגיאות: `role="alert"` + `aria-invalid` + `aria-describedby` על השדה; מצב לא בצבע בלבד (אייקון + מלל).
- **LG-47** `prefers-reduced-motion` מכבה את כל התנועה; תוכן לעולם לא מתחיל ב-`opacity:0` (ה.4).
