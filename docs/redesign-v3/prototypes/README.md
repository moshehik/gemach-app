## איך פותחים
פותחים את `archetype-detail-card.html` ישירות בדפדפן (לחיצה כפולה / גרירה לחלון). אין שרת ואין התקנה. בלי אינטרנט הגופן נופל ל-Heebo/גופן מערכת — הכול עדיין עובד.
למעלה יש **"בקרת הדגמה"** (מסגרת זהב מקווקו) — היא לא חלק מהעיצוב. היא מחליפה פרופיל ארגון, נתונים, מצבי טעינה, ערכת נושא של חלוניות, ופותחת כל סוג חלונית.

## מה לבדוק (רשימה לבעלים)
1. **שפה חזותית** מול סקיצה B: סרגל עליון navy עם קו זהב, רייל navy בצד שמאל, כפתור ראשי זהב אחד לאזור, כפתורים משניים אפרסק, Rubik גדול ומרווח.
2. **נתון בשורה**: בטאב "פרטים" — תווית קטנה מעל, ערך גדול מתחת; נתון חסר = "חסר" עם אייקון זהב (נסו בקרה → נתונים "דליל").
3. **עריכה ורשימת שינויים**: "עריכה" → שנו טלפון/עיר → כל שינוי מופיע ברייל עם "לפני → אחרי", אפשר לבטל שינוי בודד ואז להחזיר אותו. השדה שהשתנה מקווקו (ממתין). הטאב מקבל נקודה מקווקו.
4. **שמירה**: "שמירת השינויים" ברייל → פס עליון כחול עם **פס זהב יורד (15 ש׳)** — ריחוף עוצר אותו; "להיסטוריה" מעביר לטאב ההיסטוריה ושם מופיעה הרשומה החדשה.
5. **שגיאות**: מחקו שם פרטי ושמרו → הודעה בשדה עצמו + toast בפינה השמאלית-התחתונה (לא `alert`).
6. **יציאה עם שינויים**: החץ הימני (חזרה) → חלון תלת-דרכי.
7. **מייל**: "מייל ללקוח" → חלון קוד מנהל (כהה/בהיר לפי המתג; קוד 0000 = שגוי ומדגים רעידה) → חלון הזנה בהיר תמיד. ✕ עם תוכן → חלון אישור שני מעל הראשון.
8. **חסימה**: באנר בטאב פרטים; "ביטול החסימה" רק כש"העובד מהנהלה ראשית" מסומן בבקרה, אחרת מופיע מנעול עם הסבר.
9. **חוב**: טאב "תשלומים" — אריח היתרה (חוב/זכות/מאוזן — אייקון + מילה, לא צבע בלבד) + טבלה של 3 עמודות ושורה מורחבת.
10. **שכבות**: כל חלונית מכסה את כל המסך כולל הסרגל העליון, העמוד מאחור לא גולל ולא נגיש (inert), Esc סוגר רק את העליונה, הפוקוס חוזר לכפתור שפתח.
11. **רספונסיביות**: <1024 הרייל הופך לפס תחתון + גיליון תחתון, ו"במבט אחד" עולה מעל הטאבים; <640 חלון אישור/קוד = גיליון תחתון, חלון הזנה = מסך מלא; הטאבים גוללים אופקית.
12. **org variance**: בחרו "קיצוני" או סמנו "תוויות וערכים ארוכים" — שם של 60+ תווים, סכומים של 7 ספרות, סיבת חסימה ארוכה, שם סניף ארוך — הפריסה לא נשברת. "קטע הסכמה לדיוור" מסתיר/מציג שדה בלי להשאיר חור. "לקוח חדש" מראה כוכביות חובה שמשתנות לפי הפרופיל.
13. **RTL**: חץ "חזרה" מצביע ימינה; "פתיחת הזמנה", "להיסטוריה" ו"לפני → אחרי" מצביעים שמאלה; חיצי מקלדת בטאבים: שמאלה = הבא.
14. **תנועה**: אייקונים זזים בריחוף/מיקוד (חץ נוגע, רענון מסתובב, פעמון מתנדנד…). מתג "הדמיית הפחתת תנועה" (או הגדרת המערכת) מכבה הכול; פס הזהב ממשיך לרדת.

## מה נבדק בפועל (ומה לא)
- **נבדק** (Chromium headless דרך Playwright, 2026-09-24): טעינה ב-360/768/1024/1440 בלי שגיאות JS; `scrollWidth ≤ clientWidth` בכל הרוחבות (אין גלילה אופקית של המסמך) ואף אלמנט שחורג מהמסך (מלבד טאבים/טבלה שגוללים בתוך עצמם); זרימה אוטומטית: עריכה → רייל/גיליון → קוד מנהל → חלון מייל → Esc → חזרה עם שינויים → שמירה ויציאה; `data-v3-lock` פעיל והעמוד `inert` כשחלונית פתוחה; שתי שכבות נערמות (חלון מייל + אישור סגירה) ו-Esc פעמיים סוגר את שתיהן ומשחרר את הנעילה; ביטול+החזרה של שינוי בודד; פרופיל "קיצוני" וטופס "לקוח חדש" עם שגיאות — בלי גלישה אופקית. הבדיקה מצאה שני באגים שתוקנו: toast ופס עליון כיסו חלונית פתוחה (Q15).
- **נבדק בעין** על הצילומים: כיווני חצים (חזרה = ימינה, קדימה = שמאלה), מיקום רייל משמאל, toast בפינה שמאלית-תחתונה.
- **לא נבדק**: קורא מסך אמיתי, Safari/iOS (safe-area, `100dvh`), מקלדת וירטואלית, ניגודיות מדודה (axe) — רק עין, תנועה בפועל בהגדרת מערכת "הפחתת תנועה" (נבדק רק מתג ההדמיה בקוד). הגופן Rubik לא נטען בחלק מהצילומים (רשת), ולכן חלק מהצילומים בגופן חלופי.
- זה **לא** בנוי על ספריית `app/v3` (שלב 1 עוד בבנייה בענף אחר) — ה-CSS/JS כאן מקומיים לקובץ, ושמות ה-tokens (`--v3-*`) תואמים את החוקה כדי שיהיה קל להעביר.
