## 2. המיזוג עם בסיס B
- **צבעים**: רקע `--sky-200` עם שני הילות רדיאליות (כמו `body` של B, שורה 39); כרטיס לבן ממוסגר `1.5px solid --sky-300`, צל `--sh`; כפתור ראשי navy; זהב רק להדגשה (המילים בכותרת, טבעת מיקוד, קו מתחת לשם). אין ערך קשיח - רק טוקני v3 (R2).
- **פס מותג עליון** = navy (`--navy`), לוגו + "גמ"ח" + תג משנה בשתי שורות; זה הפס היחיד שלא ניווט.
- **טיפוגרפיה**: בסיס 16px, כותרת הכרטיס 28px/700 עם `letter-spacing:-.3px` (כמו `.ttl h1` של B), כותרת האייד 44-48px, מרווחי שדות 8px-scale נדיבים (R14); תווית מעל שדה (R15).
- **איקונים מונפשים** (R12): מנעול (מתרומם עם `hover`/הצלחה), משתמש (נכנס בפופ ב-`popin` כשנבחר עובד), מגן (בהופעת "מחשב מהימן"), כפתור כניסה: חץ שנע 3px; טעינה = spinner. כולם כבויים ב-reduced-motion.
- **מסגרות** (R13) לכל שדה וחלונית; `focus-visible` = טבעת זהב.
- **הסברים** (R11): "מה זה קוד מקוצר?" ו"מחשב מהימן" כ-`ⓘ` בריבוע צף, לא כפסקה.
- **מלל חדש** (R10) - הצעה: כותרת "ברוכים הבאים חזרה"; תת: "בחרו את שמכם והזינו את הקוד". אייד: "כל הגמח, / במקום אחד"; יתרונות: הזמנות והשכרות / מלאי וזמינות / תשלומים ומעקב. (לאישור המשתמש - QUESTIONS.)
- **מצב חלונית** (`isModal`, ראו §3): אותו כרטיס בלי האייד ובלי פס מותג, ברקע מטושטש; **טופס = מידע ← בהיר בלבד (R19)**.
- **מובייל**: אייד מצטמצם לכותרת בלבד; כרטיס ברוחב מלא; כפתור כניסה 52px; מקלדת: `inputmode` לא משתנה (ראו אזהרת autofill).

### 3.8 **אין** בקוד הנוכחי (לא להמציא)
- **אין בורר מוסד/ארגון**: כל אתר = גמח אחד (יש שני פרויקטי Vercel נפרדים - גמח ראשי ו"נווה יעקב", כל אחד עם מסד נתונים משלו). לכן "לאיזה מוסד מתחברים?" של מדפיס-בוט **לא מיושם**; מיפוי: **בורר העובד הוא "הכרטיסים"** שבהם משתמשים במקום. אם המשתמש ירצה אחר כך בורר גמח - זו פונקציונליות חדשה, לא קוסמטיקה (QUESTIONS).
- אין אימות דו-שלבי, אין "זכור אותי", אין הרשמה. אל תוסיפו.
- אין תמונות עובדים (בניגוד ל-Avatar של מדפיס-בוט) - אפשר להציג ראשי-תיבות בלבד, בלי קריאת API נוספת.

**שלבים בתוך אותו כרטיס** (fade, לפי STEPPER-PATTERNS #5-#6): `כניסה` -> (`שכחתי סיסמה` = תת-מסך עם "חזרה לכניסה") ; `כניסה` -> `סיסמה חדשה` (2 צמתים: הזדהות / סיסמה חדשה). ההחלטה אם להעביר דיאלוגים לתוך הכרטיס או להשאירם חלוניות היא בחירת עיצוב בלבד - בשני המקרים הלוגיקה (`forgotOpen`/`resetRequired`) לא משתנה. במצב חלונית (`isModal`) נשארים חלוניות כפי שהיום כדי לא לשבור את זרימת UserMenu.

## 5. סיכוני מימוש (לבדיקת סוכני ב')
1. **hydration**: `name` האקראי חייב להישאר ב-`useEffect`; לא להוסיף `Math.random` ב-render.
2. **autofill של כרום**: לא להוסיף `name`/`autoComplete` שונים; לא לעטוף את השדה ב-`<datalist>`.
3. `finishLogin` = `reload()` ולא ניווט.
4. `LoginScreen` משמש גם ב-`layout.js` (מחוץ ל-`PopupProvider`/`LabelsProvider`) - אסור להסתמך שם על קונטקסט; ספריות v3 חייבות להיטען גלובלית (`tokens.css`) ולא ב-provider.
5. דיאלוג סיסמה חדשה אינו ניתן לסגירה - להשאיר כך.
6. `punch-clock/page.js` משכפל חלקית את דפוס ה-autofill (שורות 130,140) - לעצב באותו כרטיס אך בנפרד.
