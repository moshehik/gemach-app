# בדיקת נאמנות לעיצוב - דף הלו״ז (`/schedule`)

מריץ ב-Chrome headless את **הדף האמיתי** (`ScheduleDay` + `schedule.css` + הפלטה + כל קבצי ה-CSS הגלובליים של האתר, עם `/api/schedule` מדומה)
מול **העיצוב המאושר** (`תצוגות-עיצוב/לוז-יומי.html`), עובר על כל מצב של הדף, ומשווה לכל רכיב את ה-computed style (רקע, תמונת רקע, טשטוש,
צבע, גבול, צל, רדיוס, שקיפות, גופן, גודל, משקל, ריפוד, סמן, משך מעבר, גובה) ואת מלבני המיקום (ימין/שמאל/רוחב/גובה-עליון, RTL).
מדפיס רק הבדלים + רכיבים שקיימים רק בצד אחד. אותה שיטה כמו `scripts/home-bg-audit` ו-`scripts/stock-bg-audit`.

```
node scripts/schedule-bg-audit/run.mjs            # 1280px
node scripts/schedule-bg-audit/run.mjs 375        # נייד
SKIP_BUILD=1 node scripts/schedule-bg-audit/run.mjs   # בלי בנייה מחדש
```

פלט: `scripts/schedule-bg-audit/out/` - צילומי מסך `real-<רוחב>-<מצב>.png` / `demo-<רוחב>-<מצב>.png`, JSON, ו-`report-<רוחב>.md` (טבלת ההבדלים לפי מצב).
בסוף: `TOTAL style diffs N | structural M`, ואז **סיווג** (`cmp.mjs`, `== CLASSIFIED`) של כל הבדל:
- `REAL` - הבדל עיצוב שלא מוסבר (ברירת המחדל: כל מה שלא מסווג במפורש). אלה נכתבים ברשימה נפרדת בסוף ובדוח.
- `PENDING` - חריץ שעוד לא חובר (כלי XL/הורדה/הדפסה עד מיזוג אשף ההדפסה, שורת הברקוד עד `onScan`): סמן `not-allowed`.
- `SHELL` - נובע מהמעטפת (index.html מדמה את `.content` של A5 עם ריפוד 14px - כך גם בפרודקשן): בצר הדף צר ב-28px.
- `NOISE` - נתוני ההדמיה שונים מנתוני העיצוב, שלב אנימציה, גובה חלון לפי תוכן, או העיצוב עצמו שבור (375).
- `KNOWN` (מבנה) - הבדל מבני מתועד: החלטת בעלים, שאלה פתוחה, או רכיב מאושר (ר' `docs/ui-fidelity-schedule.md`).
הכללים כתובים בראש `cmp.mjs` עם הסיבה לכל אחד; הסיווג לא מסתיר שורות - הן כולן בדוח, עם התווית.
הסבר לכל שורה שנשארת: `docs/ui-fidelity-schedule.md`.

## דרישות
- Chrome מותקן (`C:/Program Files/Google/Chrome/Application/chrome.exe`, אחרת `CHROME_PATH=...`).
- `puppeteer-core` ו-`react` מ-`node_modules` של הפרויקט, ו-`esbuild` (לא תלות של הפרויקט: `npm i --no-save esbuild`, או `ESBUILD_DIR=<נתיב לתיקיית esbuild>`).
- קובץ העיצוב: `DEMO_HTML=file:///...` (ברירת מחדל: `תצוגות-עיצוב/לוז-יומי.html` בשולחן העבודה של הבעלים).
- פורט השרת הסטטי: `AUDIT_PORT` (ברירת מחדל 5183). **לא** פורט 3000. אין DB: ה-API מדומה ב-`entry.jsx` (היום של ההדמיה: 4.10.2026, יום ראשון).

## המצבים
היום (שורות): ריחוף שורה, ריחוף חץ לכרטיס, לחצן "בוצע" (ריחוף / מיקוד / לחיצה), "הכל בוצע", כלי XL/הורדה/הדפסה של שלב, ציר (ריחוף, סינון),
מתג שורות/טבלה, "הוחזר לא תקין" בריחוף;
סימון "בוצע" מלא: חלון "בטוח?" (`06b`, root = `.scrim`), טוסט (`06c`, root = `#toast`), השורה אחרי הסימון וריחוף על "בוצע" דלוק
(`06d`/`06e`), חלון "הכל בוצע" (`07c`), "הוחזר לא תקין": ריחוף, חלון, טוסט, השורה עם "לא תקין" (`11b`-`11e`); טבלה (+ריחוף שורה); בורר התאריך (ריחוף על האייקון, "היום", "מחר", "הקודם", לוח עברי פתוח, ריחוף על יום);
יום שעבר (התראות איחור, שורות שבוצעו); יום עתידי; יום ריק; טעינה; בלי הרשאה (בעיצוב: אורח); עובדת (בלי הערות פנימיות / "הכל בוצע" / XL).
רק בדף האמיתי (אין להם מצב בעיצוב): שגיאת שרת, יום לא עובד, סינון סניפים, טבלת הסימונים חסרה (`marks:false`), אורח במצב פתוח בלי הרשאת סימון (`canMark:false`).

## הבדלים מוכרים שאינם באגים
- `[cur] not-allowed`: XL / הורדה / הדפסה ושדה הברקוד כבויים עד שאשף ההדפסה ו-`onScan` מחוברים (`ScheduleToolbarSlots.js`, `StageRail.js`). לחצני "בוצע" / "הכל בוצע" מחוברים (`useStageMarks.js`) - ה-API מדומה ב-`entry.jsx`.
- ערכים שתלויים בנתוני ההדמיה (שלבים ריקים `fut`, מונה 0, "בוצע" דלוק/כבוי), ובריחוף שהצליח רק בצד אחד (העיצוב פותח חלון "בטוח?" בלחיצה).
- "חסר בדף": גלגל ההגדרות (S07, מוצג רק כשיש `onSettings`), "N אירועים" בכותרת השלב ו"אין פעולות" מתחת לשם שלב ריק בציר (החלטות הבעלים 4.10.2026), `div>b`/`div>.ln` של השורה (בדף הם בתוך לחצן ההרחבה, B05/B07).
- "רק בדף": שבב "יום לא עובד" (`lz-offday`, SCH-CHIP-NWD 4.10.2026), לחצן ההרחבה של השורה (`lz-tbtn`, B05/B07), שבבי מידע במיקומים שאושרו (B08/B21), שבב "משמרת"/"שעות איסוף" (S08/B13), בורר הסניפים (נווה יעקב).
- בעיצוב ברוחב 375 הכותרת "לוח זמנים" נשברת לאות בשורה (באג של הדף הסטטי, `.ttl{display:contents}`); בדף האמיתי היא בשורה אחת.
